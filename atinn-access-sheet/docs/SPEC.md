# アクセス案内シート自動生成ツール 仕様書

マンスリーマンション（アットイン）の営業が、お客様への提案用に配る **A4横1枚の案内シート** を自動生成するWebツール。

- 2つのパターンを切り替えて作る。
  - **パターン1：物件 → 主要駅**
  - **パターン2：目的地 → 3物件**
- 完成見本は `reference/` にある。見た目はこの2枚に合わせること。
- 検算用のデータは `testdata/` にある。

---

## 1. 利用者と使い方

- 利用者は社内の営業担当。複数人で使う。
- 1枚作るのに数分かかってよい。正確さを優先する。
- 流れは次の4ステップ。
  1. **入力：** パターンを選び、URL・目的地・利用期間などを入れる。
  2. **自動調査：** 物件情報・料金・所要時間・ランドマークを集める。
  3. **確認・修正：** 調査結果を表で表示し、営業が数字を直せるようにする。所要時間・料金・強みタグ・見出しなど。
  4. **生成：** シートを表示し、PDFとPNGでダウンロードできるようにする。

確認・修正のステップは必須。自動調査の結果を、そのままお客様に出さないため。

## 2. 入力

### パターン1：物件 → 主要駅
| 項目 | 必須 | 例 |
|---|---|---|
| プランURL | ○ | `https://atinn.jp/plan/33705` |
| チェックイン日 | △ | 2026-10-01（未入力なら翌月1日） |
| 人数 | △ | 1（初期値1） |

### パターン2：目的地 → 3物件
| 項目 | 必須 | 例 |
|---|---|---|
| 目的地 | ○ | 「大手町」「〇〇株式会社 本社（住所）」 |
| 目的地の種類ラベル | △ | お勤め先／学校／病院 など（初期値「お勤め先」） |
| プランURL ×3 | ○ | `https://atinn.jp/plan/33492` ほか |
| 利用期間（チェックイン・アウト） | △ | 未入力なら30日（チェックイン＝翌月1日） |
| お客様名 | △ | 入れたときだけ右上に「〇〇様へのご提案」の札を出す |

- 物件URL（`/building/…`）でも受け付けてよい。ただし料金はプランページにしかない。
- 物件ページからはプランの一覧が取れなかった（JSで描画されていると思われる）。なので基本はプランURLを入力してもらう。

## 3. データ取得

### 3.1 プランページ（`https://atinn.jp/plan/{id}`）

取る項目：
- プラン名、物件名
- 住所
- Googleマップの座標：ページ内に `maps.google.com/maps?q=lat,lng` がある
- 交通：駅名・路線・徒歩分。複数ある
- 築年月・構造・階数
- 主な設備
- 写真とキャプション
- 禁煙／喫煙
- 設定人数・最大人数
- 「ご利用料金(１ヶ月以上)」セクションの料金

料金セクションの本文はこうなっている（2026-09時点の実例）：
```
ご利用料金(１ヶ月以上)
利用料(賃料+水道光熱費)  7,460
賃料:6,580
水道光熱費:880
キャンペーン  1月27日～1月31日までにご利用開始の方限定  3,560
※原則、ご延長時は定価でのご案内となります。
ルーム クリーニング  48,400
キャンペーン  24,200
住宅保険  1ヶ月あたり830
```
- 利用料・賃料・水道光熱費は **円/日**。
- 「キャンペーン」の値があればキャンペーン価格として使う。
- キャンペーンの **期間表記（「◯月◯日〜◯月◯日利用開始」など）はチェックしない**（営業の運用に合わせる）。キャンペーン価格があれば常にそれを使う。
- HTMLの構造（セレクタ）は未調査なので、実装時に実物を見て決めること。サイトの改修に備えて、パースに失敗したら確認画面で手入力できるようにする。

### 3.2 所要時間（乗換）

- **定義：** 所要時間＝「物件から駅までの徒歩（ページ記載の値）＋乗車時間」。乗車時間は乗換案内の値で、乗換時の歩き・待ちを含む。改札・ホームでの最初の待ち時間は含めない。日中の平日ダイヤで調べる。
- **最寄駅の選び方：** 物件の最寄駅の中から、目的地までの合計がいちばん短くなる駅を選ぶ。
  - 例：飯田橋5-1の最寄りは牛込神楽坂（徒歩3分）。ただし大手町へは乗換が要る。神楽坂（徒歩6分）から東西線なら乗換なしで合計14分なので、神楽坂を使う。
- **バスも候補に入れる。** 例：六本木4 → 渋谷は都営バス都01が最速で、乗換なし。
- **取得方法の候補（どれにするかは要相談）：**
  - A. ClaudeのAPIにweb検索ツールを付けて、駅探・NAVITIME・ジョルダンなどで調べさせる。構造化JSONと出典URLを返させる。
  - B. 乗換API（駅すぱあと・NAVITIME等）を契約する。
  - Google Maps Platformは日本の電車の経路をAPIで返さないので使えない。
- 結果は、経路の文字列・乗換回数・出典URLとあわせて保存する。確認画面で出典リンクを見られるようにする。
- 同じ区間の結果は一定期間キャッシュしてよい。

### 3.3 パターン1の主要駅の選び方
- 候補駅：新宿・渋谷・池袋・東京・品川・上野・横浜・大宮。座標は `testdata/geo_tokyo.json` にある。
- 物件からの所要時間が **31分以上の駅は外す**。
- 残った駅から、所要時間の短い順に **3つ** 選ぶ。3つに満たないときは、2つでも表示できるレイアウトにする。
- 見出しの文言は選んだ結果に合わせて変える。例：全駅30分以内なら「都心の主要駅へ、30分以内」。

## 4. 料金計算

テストは `testdata/price_cases.json` を使う。case 1 は営業のExcelと1円単位で一致を確認済み。

```
日数        = チェックアウト日 − チェックイン日 + 1   （両端を含む。10/1〜10/31 = 31日）
1日あたり   = キャンペーン価格があればそれ、なければ 利用料（賃料＋水道光熱費）
利用料合計  = 1日あたり × 日数
清掃料      = キャンペーン価格があればそれ、なければ定価
住宅保険    = 1ヶ月あたりの額 × 月数（下記の応当日ルール）
総額        = 利用料合計 ＋ 清掃料 ＋ 住宅保険
月額目安    = 1日あたり × 30
```

### 住宅保険の月数（応当日で数える）
- チェックインの翌月同日（応当日）の前日までを1か月とする。
- 1日でもはみ出したら、次の1か月として数える（端数は切り上げ）。
- 応当日がない月（1/31の翌月など）は、その月の末日を応当日とする。
- チェックアウト日が応当日と同じ日の場合（10/1〜11/1）は、2か月として数えている。**これは暫定。担当者に確認中。**
- テストは `testdata/insurance_months_cases.json` を使う。

### 追加料金（Excelにある項目。v1では任意）
- 人数追加：追加料金×人数。単価はプランページのどこに出るか未確認。
- ペット：1,320円/日（税込）
- 子ども：未就学児は無料、小学生以上は1,100円/日（税込）

### パターン1下段の「1か月／3か月」
- **1か月：** チェックインから翌月応当日の前日まで。
- **3か月：** チェックインから3か月後応当日の前日まで。
- それぞれ上の式で総額を出す。3か月は「1か月あたり」と「1日あたり」も併記する。
- 「おトク」バッジは、1か月プランとの差額が正のときだけ出す。

## 5. シートのレイアウト

- **サイズ：** A4横。1123×794px（96dpi）。1枚に収める。
- **構成（上から）：** 見出し → 路線図パネル → 下段3枠 → 注記1行。
- **フォント：** Zen Kaku Gothic New（Google Fonts）。
- **色：**

| 用途 | 色 |
|---|---|
| 地色 | `#F7F6F2` |
| 文字 | `#1E2B33` |
| サブ文字 | `#5B6770` |
| 薄グレー | `#8C959B` |
| 枠 | `#E2DED3` |
| 上部ライン | `#0F7C7A` |
| ルート色1 | teal `#0F7C7A` |
| ルート色2 | orange `#E0662A`（文字色は `#C4531A`） |
| ルート色3 | blue `#2F74B5` |
| 山手線 | `#C9CDD0`（線）／`#F3F1EA`（輪の内側の塗り） |

- **使わないもの：** 鉄道会社の公式ラインカラー、ロゴ、実在の地図タイル。資料を公開しても問題ないようにするため。

### パターン1（`reference/pattern1_property_to_stations.html`）
- **見出し：** 「都心の主要駅へ、30分以内」＋「{物件名}から主要駅へのアクセス概要図」。右上に住所（町名まで）と最寄駅2つの徒歩分。
- **路線図：** 中心は物件。主要駅3つをルート色で結ぶ。各駅に吹き出しを付ける（駅名・約◯分・乗換なし/◯回）。
- **下段3枠：**
  - **左：** 強み（紺地）。「家賃以外、ほぼかかりません」＋保証料・契約手数料0円／管理費0円／Wi-Fi無料／水道光熱費・家具家電込み。
  - **中：** 1か月プランの総額。
  - **右：** 3か月プランの総額。オレンジ枠で強調し、「おトク」バッジを付ける。

### パターン2（`reference/pattern2_destination_to_3properties.html`）
- **見出し：** 「{目的地}まで{乗換なし|◯分以内}、3つのお部屋」＋「{種類ラベル}（{目的地}）から選んだ、おすすめ物件のアクセス比較」。お客様名があれば右上に札を出す。
- **路線図：** 中心は目的地。物件A/B/Cは色付きの丸にアルファベット。物件と最寄駅を徒歩の点線で結び、駅から目的地までをルート色の線で結ぶ。吹き出しは「物件名・約◯分・乗換なし/◯回」。
- **下段3枠：** 物件カード。写真、物件名、区＋町名、最寄駅と徒歩分、「{目的地}まで 約◯分（{路線}◯分）」、1か月総額（大きく）、内訳（「1日◯円×30日＋清掃・保険」）、強みタグ。
- **強みタグ：**
  - 所要時間が最短の物件に「いちばん近い」。
  - 総額が最安の物件に「いちばんお手頃」。
  - 残りの物件は、プランページの事実から選ぶ。築年（新しい）、階数・構造、キャプション（運河沿い等）、設備など。
  - 確認画面で手で直せるようにする。

### 注記（最下行）
- 所要時間の定義（徒歩＋乗車時間の日中の目安・待ち時間は含まない）。
- 料金の基準日、人数、日数、計算式。

## 6. 路線図（いちばん大事な部分）

見本2枚は手で配置したもの。自動生成では次のルールで近づける。

### 6.1 座標変換：方角は正確に、距離は中心の近くを拡大する
1. 中心（物件または目的地）からの相対kmを出す。
   - `x = Δlng × 111.32 × cos(lat)`
   - `y = Δlat × 110.57`
2. **方位角はそのまま** にする。距離 r は `r' = a × r^0.74` で圧縮する。
   - 見本の実測：渋谷1.8km → 約140px、新宿3.8km → 約240px。
   - 近い駅は広く、遠い駅は詰めて描かれるので、1枚に収まる。
3. パネル（約1043×440〜468px）に収まるように a を決める。吹き出しの分の余白も取る。
4. 物件の周りに駅・ランドマークが密集するときは、中心付近をさらに拡大してよい。ただし **方角と「どちらが遠いか」の順序は崩さない**。
   - この順序はお客様がGoogleマップと見比べる点なので、必ず守る。

### 6.2 線のデフォルメ
- 線は縦・横・45度だけで描く（オクチリニア）。
- 経路は、途中駅の座標を同じ変換にかけて折れ線にし、それを45度単位に丸める。
- 途中駅がわからないときは、始点と終点を45度単位の2〜3本の線分でつなぐ。
- **線の種類：**
  - 電車：実線、太さ8
  - バス：破線、太さ8
  - 徒歩：点線、太さ4
- 乗換がある経路は、乗換駅で折れる。例：日比谷線で広尾→恵比寿、山手線で恵比寿→品川。
- 乗換駅は白丸で、枠線をルート色にする。
- 路線名ラベルは線の近くに小さく入れる。
- 凡例（電車・バス・徒歩）と北矢印を入れる。

### 6.3 山手線の輪（位置関係の目印）
- `testdata/geo_tokyo.json` の山手線30駅を同じ変換にかけ、閉じた輪として描く。パネルからはみ出す部分は切ってよい。
- **描き方：** 太さ12の薄グレー。輪の内側は `#F3F1EA` で薄く塗り、物件が山手線の内か外かが一目でわかるようにする。
- **駅名の表示：** 主要駅（新宿・渋谷・品川・東京・上野・池袋など）のうちパネル内に入るものに、グレーで駅名を付ける。
- **ルートとの関係：** 対象のルートが山手線を使う区間は、その区間だけルート色で上書きする。
- 東京以外のエリアでの扱いは未決定。§9を参照。

### 6.4 ランドマーク
- パネル内に入るランドマークを3〜5個、自作のデフォルメイラスト（SVG）で置く。
- 使ったイラストと座標は `testdata/geo_tokyo.json` の `landmarks` にある。
  - 使用済み：都庁、スクランブル交差点、六本木ヒルズ、東京タワー、有栖川宮記念公園、新幹線、皇居、東京駅、スカイツリー
  - 未作成（icon: TODO）：その他
- イラストは見本SVGから部品として切り出して再利用する。
- **選び方：**
  - 物件・目的地・駅の近くにあって、ラベルや線とぶつからないものを優先する。
  - 実在の建物は形を単純化した自作イラストにする。ロゴや商標は使わない。

### 6.5 ラベルの配置
- 吹き出し（駅や物件の情報）、ランドマーク、駅名ラベルが重ならないように配置する。貪欲法＋候補位置（上下左右）で十分。
- 吹き出しは、対象の点から引き出し線で結んでパネルの外寄りに置いてよい。
- 重なりが解消できないときは、低優先のもの（ランドマーク → 山手線の駅名）から外す。

## 7. 出力
- 画面にプレビューを表示する。
- PDF（A4横）とPNG（2倍解像度推奨）をダウンロードできるようにする。
- 生成に使ったデータ（入力、取得した値、出典URL、修正後の値）をJSONで保存し、同じ条件で再生成できるようにする。

## 8. 技術構成の目安（提案。変更可）
- **フロント＋API：** Next.js（TypeScript）。
- **ページ取得・パース：** サーバー側でfetchし、cheerioでパースする。
- **所要時間の調査：** Anthropic API（web検索ツール付き）で構造化JSONを返させる。またはB案の乗換API（§3.2）。
- **シート描画：** Reactコンポーネント＋インラインSVG。見本HTMLの構造をそのまま使う。
- **PDF/PNG：** Playwright（Chromium）でレンダリングする。
- **テスト：** `testdata/` のJSONで、料金・保険月数・座標変換（方位角が保たれていること）の単体テストを書く。

7. 見積もり有効期限（Excelにある）をシートにも入れるかどうか。
