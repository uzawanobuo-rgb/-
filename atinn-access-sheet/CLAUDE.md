# アクセス案内シート作成ツール：作業メモ（Claude Code 向け）

アットイン営業用の静的Webツール。ブラウザだけで動き、サーバー処理はない。
仕様・使い方は `README.md`、詳しい仕様は `docs/SPEC.md`。

## 置き場所は2つ（両方そろえる）
| 置き場所 | 内容 | 反映のしかた |
|---|---|---|
| GitHub の `main`（GitHub Pages） | 開発の本体。公開URLは README の「公開のしかた」 | PR を作ってマージ |
| 社内サーバー http://magi2.atinn.jp/access-sheet/index.html | 社員が使う本番 | `scripts/build-intranet-zip.sh` で ZIP を作って渡し、フォルダごと差し替えてもらう |

- 「両方反映して」と言われたら：main にマージ → `intranet/設置メモ.txt` の「この版で増えたこと」を更新 → ZIP を作って渡す → README の「社内サーバー版」の表に日付とコミットを足す。
- 社内サーバーは http。ブックマークレットは本体をブックマークに埋め込む形なので、`js/bm-*.js` を変えたときは全員の登録し直しが要る（`js/app.js` や `js/parse.js` だけの修正なら不要）。
- 社内サーバーはフォルダのアドレスで index.html を返さない。ツールのURLは必ず `index.html` まで書く。

## 変更するときの手順
1. `git fetch origin main` して main から作業ブランチを作る。
2. 変更する。JS を変えたら `index.html` と `view.html` の `?v=` を新しい値（例 `202611191500`）にそろえて上げる（キャッシュ対策）。
3. テスト：`node --test tests/*.test.js`（リポジトリでは `atinn-access-sheet/` の中で実行）。
4. コミット → push → PR → マージ。
5. 利用者には「Ctrl+Shift+R で読み込み直して」と伝える。

## 決まっていること（ユーザーの指示）
- サブ機能のために、主な流れや画面の配置は変えない。変えるときは先に案を出して確認する。
- リポジトリの設定（Pages・権限など）は変えない。
- Yahoo!乗換案内の経路は「乗るまでの歩き・待ち＋乗車」がいちばん短いものを選ぶ（駅前のバス停から乗る経路が選ばれて徒歩が空になる不具合があった）。
- オプション：提供エリア外でも総額には入れ、注意書きを出す（関東＝23区・横浜・川崎、関西＝大阪市・吹田、名古屋市外は在庫確認の注意だけ）。
- 1ヶ月未満のご利用：契約は最短1ヶ月、今日より前にさかのぼらない（そのときはチェックインから1ヶ月）。請求は実際の利用期間、使わない期間は値引きと書く。見積り有効期限は本日。
- キャンペーン期間と利用期間が合わないときも、料金はキャンペーン価格のまま（ツールに注意だけ出す）。
- 返事は日本語で。

## 説明資料（manual/）
- `manual/guide.html` → `node manual/render-pdf.js`：使い方ガイド PDF（A4縦10ページ）
- `manual/build-pptx.js` → `cd manual && npm install && node build-pptx.js`：初回準備と使い方の PowerPoint（15枚）
- できたものは `manual/output/`。画面写真は `manual/screenshots/`（ツールの画面が変わったら撮り直して差し替える）。

## ネットワーク
ツールの動作確認やテストデータの取得には `atinn.jp`・`transit.yahoo.co.jp` へのアクセスが要る（クラウド環境ならネットワーク設定で許可）。
